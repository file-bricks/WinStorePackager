1. TARGET PERSONAS & MARKET SEGMENTS
================================================================================

Persona 1: Solo Python Desktop App Developers & Indie Hackers
- Role: Independent software creators building Python tools (Tkinter, PySide, PyQt, CustomTkinter, Kivy).
- Core Pain: Packaging for the Microsoft Store traditionally required heavy Visual Studio installations, complex C++ project templates, or cumbersome manual XML manifest editing.
- Value Proposition: Lightweight, local-first GUI and CLI tool that handles AppxManifest.xml, multi-scale Store tile generation (44px to 310px), and automated MSIX build & sign in seconds.

Persona 2: Enterprise & Commercial Python ISVs
- Role: Software vendors and internal enterprise tooling teams distributing commercial desktop utilities to Windows Store customers.
- Core Pain: Storing code signing certificate passwords on disk or in CI configuration exposes enterprise keys; complex packaging manifests cause frequent WACK validation rejections.
- Value Proposition: Native OS Keyring cryptographic password storage (Windows Credential Vault), schema-validated AppxManifest templating, and integrated WACK report parsing with fail-closed safety.

Persona 3: Open-Source Maintainers & Cross-Platform Teams
- Role: Maintainers of open-source desktop software who develop primarily on Linux or macOS but target Windows Store distribution.
- Core Pain: Cannot run Windows SDK makeappx or signtool on Linux/macOS build servers, making pre-submission validation frustrating and delayed.
- Value Proposition: SDK-free Unix preflight (unix_preflight.py) validating project profiles, store listings, asset dimensions, and manifest schemas directly in cross-platform CI pipelines before touching Windows hardware.

Persona 4: Privacy-Conscious & Local-First Desktop Engineers
- Role: Security-focused developers building zero-telemetry, confidential, or offline desktop software.
- Core Pain: Commercial packaging solutions frequently inject cloud telemetry, analytics trackers, or require subscription accounts.
- Value Proposition: 100% offline and zero network egress guarantee (INV-LOCAL-01), unprivileged execution (RunAsInvoker non-elevation), and portable redacted project profiles (winstorepackager-project-v1.json).

4. GOVERNANCE & RUNTIME INVARIANTS
================================================================================

- INV-LOCAL-01: 100% Local-First & Zero-Egress — Manifest generation, icon processing, and preflights execute strictly offline without external network calls.
- INV-SEC-02: Cryptographic Password Protection & Non-Elevation — Certificate passwords reside exclusively in OS Keyring; runs in user space without administrator elevation.
- INV-STORE-03: Microsoft Store Manifest Compliance — Strict XML schema validation, namespace handling, and attribute escaping compliant with Microsoft Partner Center policies.
- INV-ASSET-04: Multi-Scale Asset Integrity — Automated Lanczos resampling generates exact Store tile resolutions (44x44, 50x50, 150x150, 310x310, 310x150).
- INV-PROFILE-05: Redacted Profile Portability — Shared project profiles strictly redact local machine paths, publisher IDs, certificates, and secrets for safe multi-host sharing.
- INV-CROSS-06: Cross-Platform Preflight Parity — Full preflight validation runs identically on Linux, macOS, and Windows without requiring Windows SDK binaries.
- INV-STATE-07: Host-Local State Isolation & Atomic Writes — Runtime settings and logs persist to host-local directories outside git checkouts via atomic file replacement.
- INV-WACK-08: Fail-Closed WACK Certification Evaluation — Deterministic parsing of Windows App Certification Kit reports with fail-closed rejection on errors or crashes.
- INV-I18N-09: Universal 6-Language Localization — Complete Tier-2 multilingual GUI support across German, English, Spanish, Chinese, Japanese, and Russian.
- INV-SLA-10: Vulnerability Floor & 48h Security SLA — Continuous dependency vulnerability floors, 48h security response SLA, and 5-day triage commitment.
